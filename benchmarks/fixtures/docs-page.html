Getting started

Quarry turns the data you already have into a queryable project. This page takes you from nothing to your first query in about five minutes. If you are upgrading from 1.x, read Upgrading first.

Prerequisites. A 64-bit Linux, macOS or Windows machine, and about 200 MB of free disk. No database server is needed; Quarry embeds its own. See system requirements for the full list.

1. Install the CLI

The quickest path is the install script, which needs neither sudo nor a package manager. It verifies the download against the published checksums before it installs anything.

curl -fsSL https://get.quarry.dev/install.sh | sh
quarry --version

Homebrew, Scoop and container images are covered in the installation guide, along with how to pin a version and how to verify a release signature by hand.

Shell completion

Completion scripts for bash, zsh and fish ship with the binary. Run quarry completion --help or read shell completion.

2. Create a project

A project is a directory holding a quarry.toml and the sources it reads. Create one with:

mkdir orders && cd orders
quarry init --name orders

The generated file is commented line by line; every key is described in the quarry.toml reference. Projects can also inherit settings from a profile, which is how most teams share connection settings.

Do not commit secrets. Connection strings belong in the secrets store or in environment variables, never in quarry.toml.

3. Add a source

Sources are where your data lives: CSV and Parquet files, a Postgres or MySQL database, or an HTTP API. Point Quarry at a sample file to start:

curl -fsSLO https://get.quarry.dev/samples/orders.csv
quarry source add orders.csv --name orders

Quarry infers a schema from the first 10,000 rows. You can review and override it; see schemas and overriding an inferred schema.

Databases

For a database source, store the connection string as a secret and reference it by name. Supported engines and their options are listed under Postgres, MySQL, SQLite and HTTP APIs.

4. Run your first query

Queries are plain SQL with a few extensions for time series and nested data:

SELECT customer_id, count(*) AS orders, sum(total) AS revenue
FROM orders
WHERE placed_at >= now() - interval '30 days'
GROUP BY customer_id
ORDER BY revenue DESC
LIMIT 10;

Save it as top-customers.sql and run quarry query top-customers.sql. Results print as a table by default; add --format json or --format csv for machine output. The query API runs the same file over HTTP.

How results are cached

Results are cached per source version, so a repeated query over unchanged data returns instantly. Read caching to tune or disable it.
