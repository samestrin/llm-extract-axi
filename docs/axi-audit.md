# AXI audit: llm-extract against the ten principles

A hand audit of `llm-extract` against the ten principles on https://axi.md. `axi-axi` is not installed on the build host. Every probe ran against `./build/llm-extract` from `make build`, in an empty directory with `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` unset, against a local `python3 -m http.server` page.

- **Audited:** 2026-11-11, on `main` at `4a73d42` — the code the `v1.1.0` release tag will carry. Every `file:line` and probe in this document was checked against that revision; since then `main` has moved to `1de7206` (#36 dated the CHANGELOG's 1.1.0 section, #37 rewrote the README and moved prose into `docs/`, #38-#40 added these docs); the only non-docs change is an added test file, `internal/extract/commands/readme_test.go`, which shifts no line numbers, so every `file:line` below still holds at `1de7206`. The latest existing tag, `v1.0.1`, is 11 commits behind and predates the recorded exceptions and the body-cap and cancellation fixes, so it is not the audited revision.
- **Exceptions:** five stated exceptions appear verbatim below, numbered 1 to 5 in principle order, each under its principle. Two gaps found in an earlier pass (the missing remote body read cap and missing cancellation on `extract-links` and the `extract-relevant` page fetch) are both fixed on `main` (`internal/extract/commands/capped_body_test.go`, `remote_cancel_test.go`), so nothing is left to list for them.

**Summary:** met: 2, 4, 5, 8, 10. Met with a stated exception: 1 (Exception 1: `fetch` is not TOON), 3 (Exception 2: `fetch` has no `--full`), 6 (Exception 3: plain-mode errors stay on stderr), 7 (Exception 4: `setup` has no Codex or OpenCode target and no session-end hook), 9 (Exception 5: `help[]` is `--axi` only). No principle is unmet, and no gap is left unnamed.

## Principle 6 in detail

- **Met: runtime errors are structured on stdout under `--axi`, with nothing on stderr.** `extract-relevant` with no API key under `--axi` prints `error: true` / `message: "API key is required: ..."` / `help[2]` on stdout, exit 1, stderr empty (probe). A failed `fetch` (probe: HTTP 404 exits 1 with the reason), a bad URL (`errInvalidURL`, `root.go:258`) and a missing API key all follow the same path: `axiErrorDoc` encoded by `output.EncodeAXI` to stdout (`root.go:252`), with `wantAXI` scanning the raw arguments when flag parsing stopped early (`root.go:269-273`). A result that already carries its error is not printed twice (`reportedError`, `root.go:259-264`; `TestAXIReportedResultErrorIsPrintedOnce`). Tests: `TestAXIErrorsGoToStdoutAsTOON`, `TestAXIExtractRelevantOutputFileFailureStillPrintsError` (`axi_errors_test.go`).
- **6a. Mid-run failures keep the partial result and still exit non-zero.** When `extract-links --context` ranking fails, every unranked heuristic link is printed after the error (`TestExtractLinksRankingFailureKeepsEveryHeuristicLink`, `TestExtractLinksRankingWithNoKeyExitsNonZeroAndKeepsLinks`). When some files in an `extract-relevant` directory run fail, the rest are printed and the error reads `<n> of <total> files failed (first: ...)` (`extract_relevant.go:544`; `TestExtractRelevantDirectoryWithAFailedFileExitsNonZeroAndKeepsTheRest`). Under `--axi` the result carries the `error` field, so one stream holds both.
- **6b. Usage errors exit 2 and are structured under `--axi`.** An unknown command under `--axi` prints a TOON `error`/`message`/`help[]` document listing the commands, exit 2, stderr empty (probe). An unknown flag is named, with the command's valid flags in `flags[]`, exit 2, before any network or model call (probe; `TestAXIUnknownFlagListsValidFlagsAndCallsNothing`). Exit 2 for a malformed invocation is the go-axi convention (`goaxi.ExitUsage`, `pkg/output/exit.go:66`) and is not listed as a gap.
- **6c. Plain-mode errors stay on stderr (Exception 3).** Without `--axi` or `--json`, errors print as `Error: ...` on stderr (`root.go:241-244`; probes: unknown command and unknown flag both print on stderr, stdout empty). This is deliberate. Test: `TestPlainErrorsStayOnStderr` (`axi_errors_test.go`).
- **Met: never prompts, idempotent setup.** Nothing reads a terminal. The one mutating command, `setup`, is idempotent — a second run changes nothing (`TestSetupIsIdempotent`) — and `--dry-run` writes nothing (`TestSetupDryRunWritesNothing`).

## Not probed

The model-call paths of `extract-links --context` and `extract-relevant` were not probed end to end: there is no LLM endpoint on the build host and tests use `httptest` fakes (AGENTS.md forbids network in tests). Their failure and output shapes are covered by the fake-endpoint tests named above.
