# AXI audit: llm-extract against the ten principles

A hand audit of `llm-extract` against the ten principles on https://axi.md. `axi-axi` is not installed on the build host. Every probe ran against `./build/llm-extract` from `make build`, in an empty directory with `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` unset, against a local `python3 -m http.server` page.

- **Audited:** 2026-11-11 on `4a73d42`, re-pinned 2026-11-24 to the `v2.1.1` tag, on `main` at `196d678` — the merge commit of PR #80, the commit `v2.1.1` carries. Every probe below was re-run with the `v2.1.1` binary built there (`--version` prints `2.1.1`), and every `file:line` pointer was checked against that source: 64 land on the same line there and on `main`, and the six that differ are listed below with their `196d678` lines. Each `file:line` sits next to the symbol it points at, so a moved line can be found by name, and `TestAXIAuditPointersLandOnTheirSymbols` (`axi_audit_test.go`) fails when a symbol leaves its cited lines. If a later release moves the pin, re-check this audit there and re-pin it and the catalog entry's `reviewed_revision` together. Since the previous pin (`2a6c41a`, PR #77) the v2.1.1 review rounds changed behaviour this audit describes, and rows 4, 6 and 7 now say so: an `extract-relevant` directory run reads only regular files inside `--path`, skips dotfiles and credential names and counts what it skipped; `setup` refuses a target that is a link out of `--dir`; `fetch --output` is checked before the request; and a failed model call redacts secrets from the base URL. Unreleased changes on `main` after the tag (PR #81) changed `extract_relevant.go`: `runExtractRelevant` refuses a `--path` that is a FIFO or a device, `checkWritable` refuses an `-o` that exists and is not a regular file, and `processSingleFile` read a named file only as far as the model's input. Epic 12 (PRs #89–#91) then replaced that read cut with chunked reading bounded by `--max-chunks`, which row 3 now describes; the rest of this audit describes `v2.1.1`, without those changes. They also moved seven symbols in that file down. Epic 13 added `--schema` to `extract-relevant`, then validation of its answers, and each moved them down again. The pointers below give the line on `main`, so the test above holds. Six of them name a line that holds a different symbol at `196d678`, and were checked there by symbol name: at `196d678` they are at `result.Total` 257, `checkWritable` 289, `collectDirFiles` 544, `isCredentialName` 658, `ack := finalResult` 913 and `extractRelevantHelp` 936. The seventh, `firstErr`, is declared at 745 there, and line 764 cited below still uses it at both commits.
- **Scope:** the `llm-extract` CLI, `completion` included. The MCP server (`cmd/llm-extract-mcp`, `internal/extract/mcpserver`) is out of scope: it shells out to the CLI and holds no logic of its own, so its output is the CLI's.
- **Exceptions:** two stated exceptions, each named by its principle and stated verbatim in that principle's row. **Principle 3:** the model commands bound their model input (Exception 2 below, an input limit with no `--full`): `extract-relevant` reads in chunks bounded by `--max-chunks`, and `extract-links --context` cuts its ranking prompt at a fixed limit. **Principle 7:** no session-end hook, because the tool keeps no session state; the skill is a hand-written constant checked against the committed file rather than generated from the home view; and `setup` writes no Codex `[features].hooks = true`. Exception 1 is withdrawn: `fetch` now prints a TOON envelope with a size hint, `--head` and `--full` (epic 10), and the `fetch` half of Exception 2 is withdrawn with it; what remains of Exception 2 is the model-input bound. The exceptions once numbered 3, 4 and 5 are withdrawn too: errors are on stdout in every format, `setup` registers Claude Code, Codex and OpenCode, and `help[]` ships with the TOON default. Two gaps found in an earlier pass (the missing remote body read cap and missing cancellation on `extract-links` and the `extract-relevant` page fetch) are both fixed on `main` (`internal/extract/commands/capped_body_test.go`, `remote_cancel_test.go`), so nothing is left to list for them.

**Summary:** met: 1, 2, 4, 5, 6, 8, 9, 10. Met with a stated exception: 3 (Exception 2: the model commands bound their model input — `extract-relevant` in chunks bounded by `--max-chunks`, `extract-links --context` with a fixed cut — an input limit with no `--full`), 7 (no session-end hook: the tool keeps no session state; a hand-written skill; no Codex `[features]` edit). No principle is unmet, and no gap is left unnamed.

## Principle 6 in detail

- **Met: runtime errors are structured on stdout under `--axi`, with nothing on stderr.** `extract-relevant` with no API key under `--axi` prints `error: true` / `message: "API key is required: ..."` / `help[2]` on stdout, exit 2, stderr empty (probe; a missing key is a usage error, like an `ANTHROPIC_API_KEY` with no `OPENAI_BASE_URL`, since the caller must fix the configuration before a retry can succeed). A failed `fetch` (probe: HTTP 404 exits 1 with the reason), a bad URL (`errInvalidURL` (`root.go:315`)) and a missing API key all follow the same path: `axiErrorDoc` encoded by `output.EncodeAXI` to stdout (`axiErrorDoc` (`root.go:295`)). On a usage error parsing may stop before the last `--axi`, so `errorFormat` (`root.go:349`) hands it to `argsFormat` (`root.go:377`), which scans the raw arguments the way pflag reads them: `--plain` or `--axi=false` gives the plain error, otherwise `--json` gives JSON, otherwise TOON; the last occurrence of each flag sets that flag, and `--axi`, the no-op alias for the default, never undoes an earlier `--json` (`extract-links --json --nope --axi` prints JSON). The argument after a flag that takes a value is that value, so in `--url --axi --bogus` the `--axi` is the URL and the error is the default TOON (`TestDocsStateTheFormatPrecedence`, `ac5_rerun_test.go`; `TestUsageErrorHonoursLastAXIOccurrence`, `release_gate2_test.go`; `TestRunValueFlagSwallowsAXI`, `release_gate_test.go`). A failed model call's message carries no secret from `OPENAI_BASE_URL`: a password and the values of query parameters named like a key, token, secret or signature print as `REDACTED` (`redactErr` (`pkg/llmapi/redact.go:61`); probe: a base URL `http://user:pw@127.0.0.1:1/v1?api_key=...` fails with `http://user:REDACTED@127.0.0.1:1/v1?api_key=REDACTED` in the error; `TestModelErrorDoesNotPrintBaseURLSecrets`, `TestRequestErrorsRedactBaseURL`). A result that already carries its error is not printed twice (`reportedError` (`root.go:330-332`); `TestAXIReportedResultErrorIsPrintedOnce`). Tests: `TestAXIErrorsGoToStdoutAsTOON`, `TestAXIExtractRelevantOutputFileFailureStillPrintsError` (`axi_errors_test.go`). With `-o FILE` under `--axi` or `--json`, stdout is still one structured document: the result without the passages, which stay in the file (`ack := finalResult` (`extract_relevant.go:1058`)), or on a failed `--axi` run only the `error`/`message`/`help[]` document, stderr empty (probe: a failed `-o` run with no API key). The three-line `Extracted content written to:` summary is plain mode only. Tests: `TestAXIExtractRelevantOutputFileWriteFailureIsOneTOONDocument`, `TestAXIExtractRelevantOutputFileSuccessIsOneTOONDocument`, `TestJSONExtractRelevantOutputFileStdoutIsOneJSONDocument`, `TestPlainExtractRelevantOutputFileStillPrintsSummary` (`output_file_stream_test.go`).
- **6a. Mid-run failures keep the partial result and still exit non-zero.** When `extract-links --context` ranking fails, every unranked heuristic link is printed after the error (`TestExtractLinksRankingFailureKeepsEveryHeuristicLink`, `TestExtractLinksRankingWithNoKeyExitsNonZeroAndKeepsLinks`). When some files in an `extract-relevant` directory run fail, the rest are printed and the error reads `<n> of <total> files failed (first: ...)` (`firstErr` (`extract_relevant.go:825`); `TestExtractRelevantDirectoryWithAFailedFileExitsNonZeroAndKeepsTheRest`). Under `--axi` the result carries the `error` field, so one stream holds both.
- **6b. Usage errors exit 2 and are structured under `--axi`.** An unknown command under `--axi` prints a TOON `error`/`message`/`help[]` document listing the commands, exit 2, stderr empty (probe). An unknown flag is named, with the command's valid flags in `flags[]`, exit 2, before any network or model call (probe; `TestAXIUnknownFlagListsValidFlagsAndCallsNothing`). The same holds for the wrong number of arguments (`fetch` with no URL or two, or an extra argument to `setup`, `extract-links` or `extract-relevant`, which lists the command's flags: `noArgs` (`root.go:321`)), a missing `extract-relevant --path`, a bad number (`--max-bytes`, `--timeout` or `--concurrency` below 1, `--retries` below 0: `atLeast` (`fetch.go:417`)), an `extract-relevant -o` path that cannot be written, checked before any model call (`checkWritable` (`extract_relevant.go:354`)), a `fetch --output` path that cannot be written, checked before the request (`checkWritable` (`fetch.go:277`); probe: `--output /nonexistent-dir/x` exits 2 and makes no request; `TestFetchChecksOutputBeforeRequest`), a rejected flag value (`fetch --format text`, or a URL that is not http or https: `fetch not-a-url` and `extract-links --url not-a-url` exit 2, with help[] saying what a valid URL looks like) and `completion` with no shell or an unknown one, which lists the shells in `commands[]` (`runCompletionWithoutShell` (`completion.go:39`); `TestFetchWrongArgCountIsUsageError`, `TestFetchUnsupportedFormatIsUsageError`, `TestCompletionWithoutAKnownShellIsUsageError`, `TestBadURLIsUsageError`). The format of a usage error is read from the command line as in the Met item above: `--plain` (or `--axi=false`) over `--json` over the TOON default, with `--axi` never undoing an earlier `--json`. `--plain` with `--json` is a usage error printed as the plain `Error: ...` line in either order, because the caller asked for text (`argsFormat` (`root.go:377`)). Exit 2 for a malformed invocation is the go-axi convention (`goaxi.ExitUsage` (`pkg/output/exit.go:86`)) and is not listed as a gap.
- **6c. `--plain` and `--json` errors are on stdout too.** When `run()` prints an error raised before any result was printed, under `--plain` (or `--axi=false`) it is one `Error: ...` line on stdout (`Error: %v` (`root.go:308`)) — an error carried inside a result prints as that result's `ERROR: ...` line instead — and under `--json` it is one `{"error": true, "message": ...}` document on stdout, or with `--min` as well the one-line `{"err":true,"msg":...}`, the abbreviated keys a minimal result uses. An error raised after a result exists is carried inside that result instead, as in 6a: when `extract-links --context` ranking fails, the unranked links are printed with an `error` field, and a missing API key exits 2. stderr stays empty, and the exit code is unchanged. Tests: `TestErrorsGoToStdoutInEveryFormat` (`errors_stdout_test.go`), `TestPlainAndJSONErrorsGoToStdout` (`axi_errors_test.go`).
- **Met: never prompts, idempotent setup.** Nothing reads a terminal. The one mutating command, `setup`, is idempotent — a second run changes nothing (`TestSetupIsIdempotent`) — and `--dry-run` writes nothing (`TestSetupDryRunWritesNothing`).

## Not probed

The model-call paths of `extract-links --context` and `extract-relevant` were not probed end to end: there is no LLM endpoint on the build host and tests use `httptest` fakes (AGENTS.md forbids network in tests). Their failure and output shapes are covered by the fake-endpoint tests named above.
