# AXI audit: llm-extract against the ten principles

A hand audit of `llm-extract` against the ten principles on https://axi.md. `axi-axi` is not installed on the build host. Every probe ran against `./build/llm-extract` from `make build`, in an empty directory with `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` unset, against a local `python3 -m http.server` page.

- **Audited:** 2026-11-11 on `4a73d42`, re-pinned 2026-11-18 on `main` at `67ab77e` — the commit the `v2.0.0` tag carries. Every `file:line` pointer below was checked against the tagged source, and the evidence now describes v2.0.0 rather than a mixture of v1.1.0 and later `main` changes. Each `file:line` sits next to the symbol it points at, so a moved line can be found by name, and `TestAXIAuditPointersLandOnTheirSymbols` (`axi_audit_test.go`) fails when a symbol leaves its cited lines. If a later release moves the pin, re-check this audit there and re-pin it and the catalog entry's `reviewed_revision` together.
- **Exceptions:** two stated exceptions appear verbatim below, numbered 1 and 2 in principle order, each under its principle. Exceptions 3, 4 and 5 are withdrawn: errors are on stdout in every format (3), `setup` registers Claude Code, Codex and OpenCode (4), and `help[]` ships with the TOON default (5). Principle 7 keeps one stated limitation with its reason: no session-end hook, because the tool keeps no session state. Two gaps found in an earlier pass (the missing remote body read cap and missing cancellation on `extract-links` and the `extract-relevant` page fetch) are both fixed on `main` (`internal/extract/commands/capped_body_test.go`, `remote_cancel_test.go`), so nothing is left to list for them.

**Summary:** met: 2, 4, 5, 6, 8, 9, 10. Met with a stated exception: 1 (Exception 1: `fetch` is not TOON), 3 (Exception 2: no command has `--full`), 7 (no session-end hook: the tool keeps no session state). No principle is unmet, and no gap is left unnamed.

## Principle 6 in detail

- **Met: runtime errors are structured on stdout under `--axi`, with nothing on stderr.** `extract-relevant` with no API key under `--axi` prints `error: true` / `message: "API key is required: ..."` / `help[2]` on stdout, exit 2, stderr empty (probe; a missing key is a usage error, like an `ANTHROPIC_API_KEY` with no `OPENAI_BASE_URL`, since the caller must fix the configuration before a retry can succeed). A failed `fetch` (probe: HTTP 404 exits 1 with the reason), a bad URL (`errInvalidURL` (`root.go:308`)) and a missing API key all follow the same path: `axiErrorDoc` encoded by `output.EncodeAXI` to stdout (`axiErrorDoc` (`root.go:294`)). On a usage error parsing may stop before the last `--axi`, so `errorFormat` (`root.go:331`) hands it to `argsFormat` (`root.go:353`), which scans the raw arguments the way pflag reads them: `--plain` or `--axi=false` gives the plain error, otherwise `--json` gives JSON, otherwise TOON; the last occurrence of each flag sets that flag, and `--axi`, the no-op alias for the default, never undoes an earlier `--json` (`extract-links --json --nope --axi` prints JSON). The argument after a flag that takes a value is that value, so in `--url --axi --bogus` the `--axi` is the URL and the error is the default TOON (`TestDocsStateTheFormatPrecedence`, `ac5_rerun_test.go`; `TestUsageErrorHonoursLastAXIOccurrence`, `release_gate2_test.go`; `TestRunValueFlagSwallowsAXI`, `release_gate_test.go`). A result that already carries its error is not printed twice (`reportedError` (`root.go:310-314`); `TestAXIReportedResultErrorIsPrintedOnce`). Tests: `TestAXIErrorsGoToStdoutAsTOON`, `TestAXIExtractRelevantOutputFileFailureStillPrintsError` (`axi_errors_test.go`). With `-o FILE` under `--axi` or `--json`, stdout is still one structured document: the result without the passages, which stay in the file (`ack := finalResult` (`extract_relevant.go:713`)), or on a failed `--axi` run only the `error`/`message`/`help[]` document, stderr empty (probe: a failed `-o` run with no API key). The three-line `Extracted content written to:` summary is plain mode only. Tests: `TestAXIExtractRelevantOutputFileWriteFailureIsOneTOONDocument`, `TestAXIExtractRelevantOutputFileSuccessIsOneTOONDocument`, `TestJSONExtractRelevantOutputFileStdoutIsOneJSONDocument`, `TestPlainExtractRelevantOutputFileStillPrintsSummary` (`output_file_stream_test.go`).
- **6a. Mid-run failures keep the partial result and still exit non-zero.** When `extract-links --context` ranking fails, every unranked heuristic link is printed after the error (`TestExtractLinksRankingFailureKeepsEveryHeuristicLink`, `TestExtractLinksRankingWithNoKeyExitsNonZeroAndKeepsLinks`). When some files in an `extract-relevant` directory run fail, the rest are printed and the error reads `<n> of <total> files failed (first: ...)` (`firstErr` (`extract_relevant.go:571`); `TestExtractRelevantDirectoryWithAFailedFileExitsNonZeroAndKeepsTheRest`). Under `--axi` the result carries the `error` field, so one stream holds both.
- **6b. Usage errors exit 2 and are structured under `--axi`.** An unknown command under `--axi` prints a TOON `error`/`message`/`help[]` document listing the commands, exit 2, stderr empty (probe). An unknown flag is named, with the command's valid flags in `flags[]`, exit 2, before any network or model call (probe; `TestAXIUnknownFlagListsValidFlagsAndCallsNothing`). The same holds for the wrong number of arguments (`fetch` with no URL or two), a rejected flag value (`fetch --format text`, or a URL that is not http or https: `fetch not-a-url` and `extract-links --url not-a-url` exit 2, with help[] saying what a valid URL looks like) and `completion` with no shell or an unknown one, which lists the shells in `commands[]` (`runCompletionWithoutShell` (`completion.go:39`); `TestFetchWrongArgCountIsUsageError`, `TestFetchUnsupportedFormatIsUsageError`, `TestCompletionWithoutAKnownShellIsUsageError`, `TestBadURLIsUsageError`). The format of a usage error is read from the command line as in the Met item above: `--plain` (or `--axi=false`) over `--json` over the TOON default, with `--axi` never undoing an earlier `--json`. `--plain` with `--json` is a usage error printed as the plain `Error: ...` line in either order, because the caller asked for text (`argsFormat` (`root.go:353`)). Exit 2 for a malformed invocation is the go-axi convention (`goaxi.ExitUsage` (`pkg/output/exit.go:86`)) and is not listed as a gap.
- **6c. `--plain` and `--json` errors are on stdout too.** When `run()` prints an error raised before any result was printed, under `--plain` (or `--axi=false`) it is one `Error: ...` line on stdout (`Error: %v` (`root.go:301`)), and under `--json` it is one `{"error": true, "message": ...}` document on stdout. An error raised after a result exists is carried inside that result instead, as in 6a: when `extract-links --context` ranking fails, the unranked links are printed with an `error` field, and a missing API key exits 2. stderr stays empty, and the exit code is unchanged. Tests: `TestErrorsGoToStdoutInEveryFormat` (`errors_stdout_test.go`), `TestPlainAndJSONErrorsGoToStdout` (`axi_errors_test.go`).
- **Met: never prompts, idempotent setup.** Nothing reads a terminal. The one mutating command, `setup`, is idempotent — a second run changes nothing (`TestSetupIsIdempotent`) — and `--dry-run` writes nothing (`TestSetupDryRunWritesNothing`).

## Not probed

The model-call paths of `extract-links --context` and `extract-relevant` were not probed end to end: there is no LLM endpoint on the build host and tests use `httptest` fakes (AGENTS.md forbids network in tests). Their failure and output shapes are covered by the fake-endpoint tests named above.
