# AXI audit: llm-extract against the ten principles

A hand audit of `llm-extract` against the ten principles on https://axi.md. `axi-axi` is not installed on the build host. Every probe ran against `./build/llm-extract` from `make build`, in an empty directory with `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` unset, against a local `python3 -m http.server` page.

- **Audited:** 2026-11-11 on `4a73d42`, re-pinned 2026-11-13 on `main` at `a886d18` — the commit the `v1.1.0` release gate ran on, which the `v1.1.0` tag carries. The two release-gate fix commits (#49, #50) moved lines in `extract_links.go`, `extract_relevant.go` and `root.go` after the first pass, so every `file:line` and probe below was checked again at `a886d18`. Each `file:line` sits next to the symbol it points at, so a moved line can be found by name, and `TestAXIAuditPointersLandOnTheirSymbols` (`axi_audit_test.go`) fails when a symbol leaves its cited lines. The latest existing tag, `v1.0.1`, predates the recorded exceptions, the body-cap and cancellation fixes and the release-gate fixes, so it is not the audited revision.
- **Exceptions:** five stated exceptions appear verbatim below, numbered 1 to 5 in principle order, each under its principle. Two gaps found in an earlier pass (the missing remote body read cap and missing cancellation on `extract-links` and the `extract-relevant` page fetch) are both fixed on `main` (`internal/extract/commands/capped_body_test.go`, `remote_cancel_test.go`), so nothing is left to list for them.

**Summary:** met: 2, 4, 5, 8, 10. Met with a stated exception: 1 (Exception 1: `fetch` is not TOON), 3 (Exception 2: no command has `--full`), 6 (Exception 3: plain-mode errors stay on stderr), 7 (Exception 4: `setup` has no Codex or OpenCode target and no session-end hook), 9 (Exception 5: `help[]` is `--axi` only). No principle is unmet, and no gap is left unnamed.

## Principle 6 in detail

- **Met: runtime errors are structured on stdout under `--axi`, with nothing on stderr.** `extract-relevant` with no API key under `--axi` prints `error: true` / `message: "API key is required: ..."` / `help[2]` on stdout, exit 1, stderr empty (probe). A failed `fetch` (probe: HTTP 404 exits 1 with the reason), a bad URL (`errInvalidURL` (`root.go:258`)) and a missing API key all follow the same path: `axiErrorDoc` encoded by `output.EncodeAXI` to stdout (`axiErrorDoc` (`root.go:252`)). On a usage error parsing may stop before the last `--axi`, so `wantAXI` (`root.go:270`) hands it to `argsWantAXI` (`root.go:282`), which scans the raw arguments the way pflag reads them: the last `--axi` wins, and the argument after a flag that takes a value is that value, so `--url --axi --bogus` prints the plain error (`TestUsageErrorHonoursLastAXIOccurrence`, `release_gate2_test.go`; `TestRunValueFlagSwallowsAXI`, `release_gate_test.go`). A result that already carries its error is not printed twice (`reportedError` (`root.go:260-264`); `TestAXIReportedResultErrorIsPrintedOnce`). Tests: `TestAXIErrorsGoToStdoutAsTOON`, `TestAXIExtractRelevantOutputFileFailureStillPrintsError` (`axi_errors_test.go`). With `-o FILE` under `--axi` or `--json`, stdout is still one structured document: the result without the passages, which stay in the file (`ack` (`extract_relevant.go:704-712`)), or on a failed `--axi` run only the `error`/`message`/`help[]` document, stderr empty (probe: a failed `-o` run with no API key). The three-line `Extracted content written to:` summary is plain mode only. Tests: `TestAXIExtractRelevantOutputFileWriteFailureIsOneTOONDocument`, `TestAXIExtractRelevantOutputFileSuccessIsOneTOONDocument`, `TestJSONExtractRelevantOutputFileStdoutIsOneJSONDocument`, `TestPlainExtractRelevantOutputFileStillPrintsSummary` (`output_file_stream_test.go`).
- **6a. Mid-run failures keep the partial result and still exit non-zero.** When `extract-links --context` ranking fails, every unranked heuristic link is printed after the error (`TestExtractLinksRankingFailureKeepsEveryHeuristicLink`, `TestExtractLinksRankingWithNoKeyExitsNonZeroAndKeepsLinks`). When some files in an `extract-relevant` directory run fail, the rest are printed and the error reads `<n> of <total> files failed (first: ...)` (`firstErr` (`extract_relevant.go:568`); `TestExtractRelevantDirectoryWithAFailedFileExitsNonZeroAndKeepsTheRest`). Under `--axi` the result carries the `error` field, so one stream holds both.
- **6b. Usage errors exit 2 and are structured under `--axi`.** An unknown command under `--axi` prints a TOON `error`/`message`/`help[]` document listing the commands, exit 2, stderr empty (probe). An unknown flag is named, with the command's valid flags in `flags[]`, exit 2, before any network or model call (probe; `TestAXIUnknownFlagListsValidFlagsAndCallsNothing`). Exit 2 for a malformed invocation is the go-axi convention (`goaxi.ExitUsage` (`pkg/output/exit.go:66`)) and is not listed as a gap.
- **6c. Plain-mode errors stay on stderr (Exception 3).** Without `--axi` or `--json`, errors print as `Error: ...` on stderr (`Error: %v` (`root.go:241-244`); probes: unknown command and unknown flag both print on stderr, stdout empty). This is deliberate. Test: `TestPlainErrorsStayOnStderr` (`axi_errors_test.go`).
- **Met: never prompts, idempotent setup.** Nothing reads a terminal. The one mutating command, `setup`, is idempotent — a second run changes nothing (`TestSetupIsIdempotent`) — and `--dry-run` writes nothing (`TestSetupDryRunWritesNothing`).

## Not probed

The model-call paths of `extract-links --context` and `extract-relevant` were not probed end to end: there is no LLM endpoint on the build host and tests use `httptest` fakes (AGENTS.md forbids network in tests). Their failure and output shapes are covered by the fake-endpoint tests named above.
